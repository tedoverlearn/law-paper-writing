# 主张与依据变化后的复查

需要从草稿整理主张表，或在材料与结论变动后追踪受影响判断时，使用本节。先在当前稿件定位相关判断，再查依赖它的解释、图表、摘要与结语。一次性审查可以直接列位置。

## 记录最需要追查的判断

有已有记录时沿用。需要重复检查时可复制 [主张表](../assets/claim-register.tsv) 至论文项目。为容易受材料或观点变化影响的判断分配稳定编号。位置写到实际稿件，如“v3 摘要第 2 句、第二节第 3 段”。保留建立联系的理由，正文中照常使用目标期刊体例。

| 字段 | 如何填写 |
| --- | --- |
| `id`、`claim`、`location` | 唯一且稳定的 `C` 加数字编号、可定位的单个判断及底稿位置。已有编号沿用，新表可从 `C01` 开始 |
| `depends_on` | 只填直接用到的已登记主张编号，多条用英文逗号隔开。无依赖时留空 |
| `sources` | 填可回查的直接材料和原文位置，如 `S01@第3页`，多条用竖线隔开。没有可填写的来源时留空 |
| `decision` | `confirmed` 为作者已确认采用，`provisional` 为暂定或待作者确认，`withdrawn` 为作者已撤回 |

先区分证据作用。材料可能直接支持事实或文本细节、提供解释的语境、反驳一个通说，或者仅有助于找到另一份材料。对阐释和价值论证，保留分析理由和关键前提。已有证据表可以引用，避免重抄原文。决定是否引用某份材料前核对授权和来源内容。

### 从草稿提取主张

以实际取得的草稿和版本为准，提取承担推理的判断及关键前提。同一判断在摘要与正文重复出现时合记多处位置。保留主张的归属、范围和强度。被引者意见按原归属记录，是否采纳依作者的说明或已确认的项目记录。仅凭草稿的断言语气无法确认作者的决定时，登记为 `provisional`，原稿表述照实概括。来源栏只填有可靠出处和定位的条目，缺项在表外说明。来源取得情况和核验结果仍在来源记录中注明。

按文中实际采用的推理建立依赖。相邻出现、使用同一引注或属于同一主题的主张，需要看推理是否真正借用了对方。两条依据可独立支撑同一结果时，在说明中交代各自的作用，避免把它们登记为必须共同成立的前提。遇到作者省略的前提、节选之外的依赖或实际的循环论证，定位稿件位置并另行说明。TSV 只登记本轮能确认的无环关系，同时交代未能登记的环节及理由。

### 写出并校验 TSV

使用 UTF-8，以真实制表符分隔六列。表头须按以下顺序，空字段保留分隔符。

```tsv
id	claim	location	depends_on	sources	decision
```

需要交付文件时，保存为 `.tsv`，内容从表头开始。聊天交付按用户要求使用原始数据或 `tsv` 代码块。论证结构、未登记的依赖和待核来源写在数据之外。可从 Skill 目录运行 `python -X utf8 -B scripts/check_claim_register.py claims.tsv --json`，核对表头、字段、依赖是否存在及是否成环。要比对正文标记，再使用下节的覆盖检查。脚本通过后仍需读稿确认每条主张、来源和依赖能否成立。

## 核对稿件编号覆盖

复查 Word 稿中的引注和主张时，在同一份交付副本先做[原生脚注结构检查](publication.md#word-原生脚注)。用 Word 显示的注号及实际脚注内容，核对每处支撑的正文判断和来源位置。脚注内部 ID、页面注号、主张 C 编号与来源 S 编号分别记录。改稿后再按下文比对编号，并按来源查询表内影响。查到的下游判断仍须回到该版正文和脚注复核。

在须与主张表对应的工作稿段落标出 `〔C01〕`，也可用独立的 `C01` 或 `[C01]`。运行下面的只读检查时，提供同一版本的 TSV 主张表和 UTF-8 `.md` 或 `.txt` 工作稿。Word 稿可导出保留节标题和编号的文本。

```sh
python -B scripts/check_claim_register.py claims.tsv --check-coverage manuscript.md
python -B scripts/check_claim_register.py claims.tsv --check-coverage manuscript.md --json
```

检查按编号逐字匹配，摘要、引言、正文和结语的段落纳入比较。脚注、参考文献和附录按可识别的节标题排除，Markdown 引语块、代码围栏和脚注定义也排除。正文有标记但主张表未登记时，报告该编号在稿件中的行列。表内已登记但正文未出现时，报告登记位置和决策状态。若只提供一章或主张表保留了撤回记录，结合本轮范围复核差异。

退出码 0 表示编号对应，1 表示存在差异，2 表示输入有误或无法读取。稿件和主张表保持原样。命题内容、引注和依赖关系沿下节另查。

## 复查依据变动的影响

有 Python 3 时，运行只读脚本查询表中记录的关系。相对路径以下例所在 Skill 目录为起点。

```text
python scripts/check_claim_register.py <论文主张表.tsv> --source S01
python scripts/check_claim_register.py <论文主张表.tsv> --claim C01
```

命令给出表内直接关联与后续依赖的位置，也可用 `--json` 交给其他工具。按原请求选择检查范围。若本轮要复查稿件，用旧版本的引文、译名、同义表述及其暗含的前提定位表外段落。逐处读上下文，区分两种情况。确实使用旧依据的片段列出所依赖的释义或推理，只有关键词相同的片段说明其独立用途。

交付时注明表里确认的关系、读稿新增的受影响位置与尚未取得的部分。只收到主张表时，可以先列应查的位置和要找的表述。涉及相互竞争的解释时说明哪一种受版本变化影响。“作者已确认”“出处已核对”和“此处推理成立”分别判断。

例：替换一份档案编校本时，先查新版本中影响解释的措辞。若该措辞支撑 C01 对发言主体的理解，查依赖 C01 的 C02 历史结论和 C03 摘要，并复核转述、译名和原注。若地图和日期部分有独立依据，按原任务处理。需要改变作者已确认的核心结论时，列出证据和可选改法。
