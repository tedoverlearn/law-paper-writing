# 主张与依据变化后的复查

这项工作用于长期论文中的核心论证，例如新找到一版史料、裁判或译文，或者作者决定改变一个概念或结论。先在当前稿件定位受影响的判断，随后检查依赖它的解释、图表、摘要与结语。一次性审查可以直接列位置。

## 记录最需要追查的判断

有已有记录时沿用。需要重复检查时可复制 [主张表](../assets/claim-register.tsv) 至论文项目。为容易受材料或观点变化影响的判断分配稳定编号。位置写到实际稿件，如“v3 摘要第 2 句、第二节第 3 段”。保留建立联系的理由，正文中照常使用目标期刊体例。

| 字段 | 如何填写 |
| --- | --- |
| id、claim、location | 稳定 C 编号、可逐句核对的一个判断及底稿位置 |
| depends_on | 本判断依赖的 C 编号，用英文逗号隔开，同一行写直接依赖 |
| sources | 用 `S01@第3页` 这样的来源编号和原文定位，多条用竖线隔开 |
| decision | `confirmed` 作者已确认采用，`provisional` 暂定，`withdrawn` 已撤回。实际核验情况在来源卡中另记 |

先区分证据作用。材料可能直接支持事实或文本细节、提供解释的语境、反驳一个通说，或者仅有助于找到另一份材料。对阐释和价值论证，保留分析理由和关键前提。已有证据表可以引用，避免重抄原文。决定是否引用某份材料前核对授权和来源内容。

## 复查依据变动的影响

有 Python 3 时，运行只读脚本查询表中记录的关系。相对路径以下例所在 Skill 目录为起点。

```text
python scripts/check_claim_register.py <论文主张表.tsv> --source S01
python scripts/check_claim_register.py <论文主张表.tsv> --claim C01
```

命令给出表内直接关联与后续依赖的位置，也可用 `--json` 交给其他工具。按原请求选择检查范围。若本轮要复查稿件，用旧版本的引文、译名、同义表述及其暗含的前提定位表外段落。逐处读上下文，区分两种情况。确实使用旧依据的片段列出所依赖的释义或推理，只有关键词相同的片段说明其独立用途。

交付时注明表里确认的关系、读稿新增的受影响位置与尚未取得的部分。只收到主张表时，可以先列应查的位置和要找的表述。涉及相互竞争的解释时说明哪一种受版本变化影响。“作者已确认”“出处已核对”和“此处推理成立”分别判断。

例：替换一份档案编校本时，先查新版本中影响解释的措辞。若该措辞支撑 C01 对发言主体的理解，查依赖 C01 的 C02 历史结论和 C03 摘要，并复核转述、译名和原注。若地图和日期部分有独立依据，按原任务处理。需要改变作者已确认的核心结论时，列出证据和可选改法。
